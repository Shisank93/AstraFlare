# AstraFlare Label Provenance & Precedence Specification

## Overview
This document defines the label provenance framework, precedence hierarchy, confidence scoring separation, and conflict resolution rules in AstraFlare.

---

## 1. Label Precedence Hierarchy

When multiple labeling sources are available for a given satellite observation, AstraFlare enforces a strict precedence hierarchy:

```text
    VERIFIED_EXTERNAL (Precedence Weight: 100)
               │
               ▼
     MANUAL_VERIFIED (Precedence Weight: 80)
               │
               ▼
        WEAK_RULE (Precedence Weight: 40)
               │
               ▼
        UNLABELED (Precedence Weight: 0)
```

> [!IMPORTANT]
> **Strict Rule:** Weak supervision rules (`WEAK_RULE`) can **NEVER** overwrite independently verified external evidence (`VERIFIED_EXTERNAL` / `MANUAL_VERIFIED`). If a weak rule disagrees with an external verified record, the external verified label takes precedence.

---

## 2. Confidence Score Separation

AstraFlare strictly distinguishes between two independent confidence concepts:

1. **Source Confidence (`source_confidence`):**
   - Measures the trustworthiness and precision of the external ground-truth source or human verification.
   - Example: NASA FIRMS NRT Catalog = `0.95`, PESO Incident Registry = `0.98`, Weak Heuristic Rule = `0.80`.
2. **Model Confidence (`model_confidence` / `probability`):**
   - Measures the output probability generated by the calibrated GBDT model (`CalibratedClassifierCV`).
   - Example: $P(\text{Industrial Incident}) = 0.82$.

These two metrics are never combined or confused in feature vectors or evaluation metrics.

---

## 3. Conflicting Evidence Resolution

If competing external evidence sources match the same physical FIRMS cluster with opposing event classes (e.g. one source reports a Natural Wildfire while another reports an Industrial Facility Flare Incident):

1. The observation label is set to `CONFLICTING_EVIDENCE`.
2. `label_confidence` is set to `0.0`.
3. `verification_status` is set to `CONFLICTING_EVIDENCE`.
4. The item is automatically routed to `HUMAN_REVIEW_REQUIRED` for analyst adjudication.
